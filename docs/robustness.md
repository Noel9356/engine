# Robustness notes

Problems found during development and the structural decision each one produced, plus the honest limits of the current design. This file is the full ledger; the per-component docs (`modules/<name>/README.md`, `kernel/README.md`, `host/README.md`) cite their problems in context where the fix lives.

## Problems found and solved

1. **Dangling construction order.** The resolver returned pointers into its internal manifest copy and the kernel iterated freed memory. Fix: results carry indices into the caller's manifest vector — no lifetime coupling.
2. **Mod entry table never called.** The kernel cast the exported function symbol to the table type and read function bytes as fields. Fix: the symbol is resolved as a function, called, and the returned table is validated field by field.
3. **Library unload before mod destruction.** `dlclose` ran while the mod instance was alive, and `delete` would have used the engine allocator on mod memory. Fix: the library handle is declared before the mod pointer (destroyed last); destruction goes strictly through the mod's own `destroyMod`.
4. **Lifecycle methods reached from the wrong side.** Module destructors ran `stop()` after a dry validation, dereferencing null capability pointers. Fix: `stop()` is defensive and the kernel destructor stops everything once.
5. **Compile time/runtime mismatch surfaced late.** A compiled-out module still listed in the configuration only failed at link time. Fix: CMake generates an availability header; the kernel reports the precise "compiled out" case.
6. **Partial diagnostics.** A wrong module name masked a denied permission (early return before the permission pass). Fix: every check accumulates into one report; the run fails once, with everything listed.
7. **Screenshot latency and correctness.** Capturing after present races the compositor. Fix: the capture copy is recorded inside the same command buffer as the frame, synchronized with the frame fence, swizzled to RGBA8 on the CPU, written once the GPU signals.
8. **Single provider ambiguity.** Two modules providing one capability is a silent ordering hazard. Fix: the resolver refuses ambiguous graphs and names the candidates plus the `[providers]` key that resolves them.
9. **Cross-thread events.** Publishing from a non-main thread would race the direct dispatch. Fix: single threaded by contract, documented; a delivery module can add queues without touching the channel API.
10. **Event storms from repeated registration.** Modules constructed twice would double subscribe. Fix: subscriptions are RAII handles released in stop; the kernel never constructs a record twice.
11. **Mods with an empty graph identity.** A shared-library mod's compiled manifest was default-constructed — no name, no edges, no permissions. Fix: packages carry `mod.toml`; the kernel takes identity and wiring from the file and cross-checks the compiled manifest's name.
12. **Header warnings leaking into engine targets.** Third-party headers tripped `-Wextra` inside engine translation units. Fix: third-party include paths are marked `SYSTEM`.
13. **Dependency acquisition guessing.** Fetching deps that already exist wastes time and breaks reproducibility. Fix: strict tier order (existing target, vendored copy, populated tree, pinned download) with a configure-time origin report; see `docs/building.md`.
14. **MinGW-built mod libraries not loadable.** MinGW prefixes module DLLs with `lib`, the kernel only accepted `<entry>.dll`, and a fully built mod failed at startup. Fix: the example mod sets `PREFIX ""` on Windows, and the loader accepts the `lib`-prefixed spelling as a fallback; naming rules are in `mods/README.md`.
15. **NOMINMAX redefinition warnings.** Per-file `#define NOMINMAX` clashed with MinGW's libstdc++, which already defines it through `<filesystem>`/`<string>`. Fix: one `add_compile_definitions(WIN32_LEAN_AND_MEAN NOMINMAX)` for the whole tree in the root CMakeLists, no per-file defines.
16. **Vulkan vocabulary in a kernel contract.** `window_contract.hpp` included `<vulkan/vulkan.h>` and exposed `VkSurfaceKHR`/`VkInstance`, and the kernel publicly linked `Vulkan::Headers` to make it compile — spreading Vulkan include paths to every kernel consumer. Fix: the window contract deals in opaque handles (`createPresentationSurface`, `requiredInstanceExtensions`), the kernel drops its Vulkan link, and a configure-time guard rejects implementation headers in contracts; see `mods/README.md`, section "Portability".
17. **Renderer warning debt against current Vulkan-Hpp.** The deprecated C-pointer `setPfnUserCallback` overload and two ignored `waitForFences` return values warned on every build. Fix: the debug callback uses the vk-namespace typed signature, and both fence waits handle `eTimeout` explicitly (skip the frame / discard the capture) instead of ignoring the result.
18. **Vertex stage silently dropped from the graphics pipeline.** `vk::GraphicsPipelineCreateInfo::setStages` takes an array proxy and replaces the whole stage list on every call; calling it once per stage left a pipeline with only the fragment shader. Validation reported "no Vertex Shader", the desktop driver created the broken pipeline anyway, and the process crashed at first draw. Fix: both stages are passed as one `std::array`, with a comment pinning the pitfall.
19. **Vulkan 1.3 features used but never enabled.** The pipeline relied on dynamic rendering (`renderPass = nullptr`) and the frame recorded `pipelineBarrier2`, but the device creation enabled neither `dynamicRendering` nor `synchronization2`, and the pipeline carried no `VkPipelineRenderingCreateInfo`. Validation flagged three VUIDs at pipeline creation. Fix: device creation enables both features through the Vulkan 1.3 feature chain, physical device selection requires `apiVersion >= 1.3`, and the pipeline receives the swapchain color format through `VkPipelineRenderingCreateInfo` — rebuilt when a swapchain recreation changes the format.
20. **Device selection rejected the only available device.** The best-score sentinel started at -1, but a CPU or software device scores below zero (base -100 plus a small limits bonus), so on a machine with only a software ICD the engine reported "no physical device" while enumerating one. Fix: the sentinel is the integer minimum; `prefer_discrete_device` is honored in scoring (it was read from the configuration but never used); every rejected candidate logs the precise reason.
21. **Per-component context dangled after construct.** The kernel created each component's `ComponentContext` on the construct loop's stack while modules and mods cached the pointer for later event publishing (input callbacks, window events, frame events, capture events). The first publish after startup read overwritten stack memory as an event bus and crashed — in the field, right after the last startup log line. Fix: each component record heap-anchors its context for the engine lifetime, the renderer caches its channel references at construct (zero per-frame lookups, per the event bus hot-path note), and a kernel regression test publishes through a cached context more than a hundred iterations after construct.

22. **Present semaphores owned by the frame slot instead of by the swapchain image.** The render-finished semaphores were sized by `max_frames_in_flight` and indexed by frame slot, so with a 3-image swapchain and 2 frames in flight the third submit re-signaled a semaphore whose signal the presentation engine could still be waiting to consume for image 0 — the field log on NVIDIA/Windows flooded with `VUID-vkQueueSubmit-pSignalSemaphores-00067` ("presented but was not re-acquired"). Semaphore ownership now follows `FrameSyncPolicy` (`modules/renderer/frame_sync_policy.hpp`): acquire semaphores stay frame-slot scoped, render-finished semaphores are one per swapchain image indexed by the acquired image index — an image cannot be re-acquired before its presentation retired, which makes re-signaling legal deterministically — and the pool is rebuilt on every swapchain recreation because a present that failed with `OUT_OF_DATE` can leave its semaphore signaled.
23. **Surface-anchored probes grazed their own surfaces and zeroed the entire GI.** Once every cascade anchored its probes on the depth surface (needed for correct positional variation), two self-intersection paths poisoned the chain: gather line-of-sight between two points of the same floor ran *along* the floor and reported it as an occluder (every probe dropped, GI black), and march rays started exactly on the surface and immediately re-hit it. Fix: both LOS endpoints leave their surfaces by one centimetre plus an end-of-line clearance buffer, march origins offset along the G-buffer normal, and hits closer than 2 cm to the origin rejected as self-hits. The leak test configuration (sealed room, no sun, no sky) made the failure unmistakable: the frame was completely black.
24. **Emissive panels are invisible to coarse cascades.** The interval x2 schedule halves the angular resolution per cascade; with an elevation floor of 2 the coarsest cascades only sample +/-45 degrees, and a ceiling panel at ~70 degrees elevation is systematically missed - the panel-only debug render was black even though hit detection worked (proved by a constant-radiance march exercise). Fix: the elevation floor is 3 (-60/0/+60 degrees), and point or sun lights are the robust transport path for strong light sources because the relight evaluates them analytically at hit points. Emissive-surface GI quality scales with `base_rays`; this is a documented quality knob, not a leak.
25. **A pass-local descriptor set layout died under a live pipeline (field-reported NVIDIA validation storm).** The PBR pass created its frame descriptor set layout as a C++ local inside `rebuild()`; the member pipeline layout and pipeline kept referencing it after the function returned, so every frame's `vkCmdBindPipeline` used a pipeline whose layout referenced a destroyed `VkDescriptorSetLayout` (`vkCmdBindPipeline(): pipeline ... references VkPipelineLayout ... which became invalid because it references deleted object VkDescriptorSetLayout`). Three structural fixes: every Vulkan object a rebuild needs to outlive the call is a declared member, members are declared so even plain C++ destruction runs in reverse dependency order, and every rebuild path (both technique passes and the renderer's `createPipelines`) tears down explicitly in the order descriptor sets, pools, pipelines, pipeline layouts, descriptor set layouts. **Visibility note:** this fired only on NVIDIA's validation layer - a 40-frame smoke run on lavapipe with layer 1.4.309 reported nothing, so this is the second documented blind spot of software-WSI verification (with problem 22's class): object-lifetime tracking differences between validation layer builds. The structural rule above is the guard; there is no honest deterministic test for object lifetime on a stack that cannot see the violation.
26. **Technique configuration was read from a section name that does not exist.** `[lighting.pbr]` in TOML creates a nested table (`lighting` containing `pbr`), but the modules read it with `"lighting.pbr"` as the *section* name; the section lookup returned null and every knob (`shadows`, `penumbra`, `cascades`, `probe_stride`, ...) silently fell back to its default. Nothing failed because the shipped defaults matched the shipped config - but the leak test ran with default GI settings, and `shadows = false` was ignored (visible as `shadows on` in the log). Fix: nested settings are read as dotted paths inside the `[lighting]` section (`"lighting"` + `"pbr.shadows"`), the leak check now runs with its actual configured values, and a debug log line (`pbr module started; ... shadows off`) reflects the parsed state. Lesson recorded: a `value_or(default)` hides a wrong section name; verify knob reads by logging one parsed value at startup.
27. **Every coarse cascade anchored its probes on unrelated surfaces, so the interval composition mixed incompatible fields.** With all cascades surface-anchored, a coarse probe anchored on whatever surface sat at its cell-center pixel - potentially a different wall than the fine probes it composed into - and its slab was measured from that anchor. The composition `full[c] = march[c] + T[c] * full[c+1]` then chained fields anchored at unrelated world points, which surfaced as giant soft blobs riding the probe grid and a dark sky-colored wash over interiors (the user-reported "blocky and weird"). Fix: intervals are measured along the VIEW ray; coarse cascades anchor on the camera ray at their slab start and march the slab in view depth (distance range per direction scales with cos(direction, ray)), so composition chains along one ray; the gather is depth selective (each pixel reads the cascade containing its depth); cascade 0 stays surface-anchored for exact near-contact transport. The camera-anchored redesign also removed the old angular halving with its 2x3 floor, which handed the whole far field six directions.
28. **Bailing out of probes anchored inside geometry blocked the light instead of guarding it.** The first camera-anchored implementation stored transmittance 0 for probes whose anchor landed in a solid (a cell's view ray exits the room through a wall before the slab start). For a camera 0.6 units from a wall this zeroed most upward/backward probes and darkened entire rooms to black. The correct split of responsibilities: the MARCH never blocks on this (it passes through with transmittance 1 when the anchor is buried - sphere tracing from inside a solid oscillates, so it bails early); whether a pixel may USE such a probe is decided where it is checkable, by the gather's line-of-sight guard, which is also what keeps the leak check green.
29. **The leak check could not see a dead GI.** Its lit region was lit by the DIRECT pass as well as by transport, so a completely dead GI path passed the automated check (discovered when the camera-anchored redesign initially killed all transport and every ctest stayed green). Fix: `config/leak_test.toml` renders with `techniques = ["radiance_cascades"]` only - the sealed region now proves the transport cannot leak and the lit region proves the transport is alive, with no direct light to mask either. Lesson recorded: an acceptance test must fail for the component it guards; if a second component can satisfy the assertion, the test tests the pair, not the component.
30. **The capture readback used the 1 s presentation fence budget.** A capture is a rare correctness-critical event, but it waited on the per-frame fence with the frame timeout - on CPU rasterizers rendering 1-2 s frames every capture was silently discarded (`frame capture fence timed out`). Fix: captures wait on their own generous 60 s budget (software rasterizers and heavy GI settings render far slower than any GPU; the fence still signals immediately on real hardware); the per-frame present path keeps the 1 s budget.
31. **The demo window opening was a third of its authored size.** The window sill and lintel panels were authored with y half-extent 0.9 at centers 0.45/2.55, so the two 1.8-unit-tall panels overlapped the intended 1.2-unit opening and left a 0.3-unit slot - the room's only sun inlet was three times too small (and the front wall segments extended 2 units past the ceiling). Sizes are HALF extents; the panels are now 0.45 half-extents and the wall segments 1.5, matching the documented 1.2 x 1.2 window. Lesson recorded: `plane` sugar does not normalize sizes; author against half extents deliberately.
32. **A debug radiance marker shipped inside the committed march stage.** The coarse-cascade miss path wrote a constant `vec4(0, 0, 10, 1)` behind a `TEMP MARKER` comment left over from debugging the composition - every coarse-cascade direction that escaped the slab contributed fake blue light at intensity 10, which surfaced as physically impossible coloring (an orange-albedo cube rendered saturated blue, a value no light in the scene can produce after albedo modulation). Worse, it masked the leak check: the marker's blue satisfied the lit-region threshold for the wrong reason, so the suite stayed green while the real transport under it was dead. Fix: the marker is removed (a miss is transmittance 1 with no radiance) and the leak check now passes on real transport. Lesson recorded: never commit past a debug visualization - a debug field that "fixes" an assertion is a bug wearing a green badge; grep the shader tree for marker/TEMP patterns before committing rendering changes.
33. **Probe-starved pixels read false black.** With the marker gone the leak check failed with `lit region luminance 0.000000` - the lit interior seen through the window was pitch black although the point light inside lights it directly. Two mechanisms conspire: the coarse grid spatially aliases the small opening, so the surrounding probes anchor on the framing wall or behind it and the line-of-sight guard correctly rejects them all; and the cascade 0 fallback anchors its probes on the deep surfaces around the pixel, where cascade 0's `[0, interval]` view-depth slab lies entirely behind the anchor - zero-length march, empty field (cascade 0's slab contract only serves surfaces within its interval of the camera). The gather then had `weightSum == 0` and wrote black, falsely reporting "no light here". Fix: a starved pixel falls back to its OWN direct radiance, computed at the pixel's own surface with the same relight the march applies at hit points (nearest-SDF primitive owns the surface; `sunDiffuse + pointDiffuse + emissive`). That term is geometrically exact for the pixel and can never smuggle light across geometry: the sealed wall stays dark because its own direct light IS dark. The leak check is the guard that turned this from an invisible quality bug into a caught regression - it now also covers the probe-starvation class.
34. **Every texture-array upload targeted array layer 0.** The staging copies built `vk::ImageSubresourceLayers(aspect, mipLevel = 0, baseArrayLayer = 0, layerCount = 1)` per set but never advanced `baseArrayLayer`, so all five sets wrote into layer 0 and each overwrote the previous - the last set won, layers 1..N were never written. Validation is silent (the copies are perfectly legal), the images are just wrong: every textured object but the last-loaded one sampled black, and objects on layer 0 sampled the WRONG set. Found by dumping the uploaded arrays back to the host and comparing pixels against the source PNGs - the fastest way to make an upload path lie visibly. Fix: `baseArrayLayer = index` explicitly; the dump harness (temporary) confirmed all layers byte-identical to their sources. Lesson recorded: array-layer indices in copy subresources are the same class of silent default as the config-section dotted paths of problem 26 - zero is valid, so nothing complains.
35. **A consecutive `std::fill_n` corrupted interleaved texel channels.** The data-map packing initializes missing channels with neutral values (roughness 0.5, metallic 0, identity normal). The metallic clear used `std::fill_n(data.begin() + 1, pixelCount, 0)` - consecutive bytes, not a stride-4 channel fill - which zeroed the first quarter of the buffer byte-by-byte and left `metallic = 128/255` (half metal!) on roughly three quarters of every non-metal texture. Consequences were object-dependent and confusing: a concrete cube rendered near black (half-metal F0, halved diffuse and GI), while larger features looked merely dark. Fix: an explicit per-texel loop writing all four channels. Lesson recorded: interleaved channel initialization must be strided by construction, not by a clever offset into a flat fill.
36. **`int(x + 0.5)` is not rounding for negative sentinels.** The G-buffer push constants carry the material layer indices as floats; the shader converted them with `int(x + 0.5)`, which truncates toward zero in GLSL - the "no texture" sentinel `-1.0` became `int(-0.5) == 0`, silently binding untextured objects to texture layer 0 (the first set) instead of the flat-material path. Fix: `int(floor(x + 0.5))`, which rounds half away from zero for negatives too. Lesson recorded: float-to-int sentinels need floor semantics in GLSL exactly as they do in C; the truncation difference only shows on the negative side, which is where the sentinel lives.
37. **A failing shader compile silently kept the previous frame's visuals.** During the debug loop, shader edits that broke GLSL compilation failed the custom command - but the build's overall failure scrolled past, the stale `.spv` from the last good compile stayed in the runtime shader directory (then `runtime/assets/shaders`, renamed to `runtime/shaders` when content moved out of the engine and shaders stopped pretending to be assets), and the engine kept rendering with old shaders while the captures appeared to "ignore" the new code. Three debug iterations were burned before the `.spv` timestamps exposed it. Fix (process, not code): shader build failures must fail loudly - the shader custom commands are checked in the verification loop (build exit code, then `ls -la` of the .spv outputs) before any capture is interpreted. Lesson recorded: when a rendering change "does nothing", suspect the build before the shader; compare SPIR-V timestamps to the edit time first.
38. **Camera-anchored probe rays marched backward past the camera plane.** The march range for a camera-anchored probe direction was `(interval.y - anchorDepth) / max(viewCosine, 0.3)`: for directions pointing AWAY from the slab (viewCosine <= 0, i.e. towards the camera) the cosine floor turned a negative advance into a positive one and handed the ray a 30 m budget through the camera plane and beyond - each probe's field for those directions described whatever far geometry the stray ray happened to hit, and every pixel integrating those directions inherited the per-probe variance as large blocky staircases riding every surface seen at an angle (isolated by visualizing single cascades' fields with and without relight shadows; the staircase followed the march, not the gather). Fix: the march range is EXACTLY the ray's segment inside the view-depth slab - forward directions `(interval.y - anchorDepth) / viewCosine`, backward directions `anchorDepth / |viewCosine|` (down to the camera plane only), cascade 0 keeps its `[0, interval]` remainder rule. Lesson recorded: an interval partition measured in one metric (view depth) bounds ray segments in another (distance along the ray) only through the exact cosine; a floor on that cosine silently converts a bounded segment into an unbounded one.
39. **The normal map's X and Y were both decoded from the red channel.** The data-map packing loaded `NormalGL.png` twice through `stbi_load(..., req_comp = 1)` - which always returns the RED channel - into the packed texel's B and A slots, so every surface's tangent-space normal was `(R, R)`: a 45-degree diagonal regardless of the map's content. Every normal-mapped surface was shaded with systematically skewed normals (the metal sphere's reflections swam, plaster and brick shading ignored bump direction), and the GI gather's LOS offsets built from those normals collapsed probe coverage on curved surfaces. Fix: load with `req_comp = 2` and take source component 0 for X and 1 for Y. Lesson recorded: `req_comp = 1` is a channel EXTRACT (red), not a grayscale conversion - two single-component loads of one RGB file return the same bytes twice.
40. **The rasterized room was half the size of the traced room.** The unit box mesh spanned +-0.5 while `modelMatrix` scales by the primitive's HALF EXTENTS - every box occupied a quarter of the volume its analytic SDF described. The demo room rendered as a half-size box floating inside the SDF's closed 7x7 room: the sky showed through the gaps between the rasterized walls (35% of the frame), GI cascade probes anchored on depth-buffer surfaces of the small geometry while LOS/march/relight used the big SDF, shadow rays hit walls that were not where the pixels were, and reflection rays relit surfaces with mismatched materials. Fix: the unit box mesh spans +-1 (the sphere mesh was already unit-radius and correct); rasterized and traced geometry now agree by construction, and the `uv_scale` semantics were pinned to the documented "world meters per texture tile" in the same pass. Found by rendering the unlit G-buffer (techniques = []) and noticing a third of the frame classified as sky inside a sealed room. Lesson recorded: when a unit mesh meets a scale constant, render one known box and measure it against the SDF before trusting either - the SDF and the mesh never share a test.
41. **The GI field carried the wrong energy unit (pi factor plus a double albedo).** The shared relight returned `albedo * irradiance` as the cascade field's "radiance", skipping the Lambert `1/pi` - every GI bounce arrived at the composite pi times brighter than the direct pass it sits next to. Worse, the gather's starved-pixel fallback fed `surfaceOutgoingRadiance` into the GI slot, which the composite multiplies by the pixel's albedo AGAIN: `albedo^2 * E * pi` bright blotches riding exactly the probe cells whose coarse coverage collapsed (the strongest remaining blockiness after the visibility work). Fix: the unit chain is now explicit and documented in `relight_common.glsl` - march hit stores `albedo * directIrradianceOverPi + emissive` (radiance), the gather integrates `sum(cos * solidAngle * L) / pi` (irradiance/pi), the composite multiplies albedo once, and the starved fallback returns `directIrradianceOverPi` directly (no albedo). Found by isolating the fallback path with reflections and GI toggled separately, then re-deriving the units. Lesson recorded: when three passes compose an energy chain, write the unit of every stage into the shared header comment; a missing factor of pi survives every functional test because nothing crashes - it only glows.
42. **A renormalization floor amplified partially blocked pixels into bright contact rims.** The gather normalized surviving probe contributions by `max(weightSum, 0.7)`: a pixel with two of four probes line-of-sight blocked got its remaining contributions divided by 0.7 - up to 1.4x amplification exactly where occluders meet surfaces (every contact silhouette gained a bright rim, and dark GI puddles around objects gained bright halos). Fix: normalize by the ACTUAL surviving weight sum (`accumulated / weightSum`, zero when nothing survives) - fully visible neighbourhoods are unchanged, the starved-pixel fallback owns the truly blocked ones, and nothing amplifies in between. Lesson recorded: a clamped denominator is an amplification knob; in a visibility-weighted blend the denominator must be the real surviving weight, with the fallback chain (not a floor) handling collapse.
43. **The mixed/pure probe-cell classification was a binary branch, banding the field in rectangles.** The march anchored a coarse cell either at its far surface (depth spread over the threshold) or at the slab start (under it); neighbouring cells classified differently carried wildly different fields, and the compose stage's bilinear interpolated BETWEEN them - rectangle-scale stair steps around every small bright emitter (the blocky halo banding on the ceiling around the emissive panel; isolated by capturing with GI only and comparing the halo edge period against the cascade cell sizes). Fix: the classification is a CONTINUOUS blend - `mixedness` ramps over the same depth-spread width the binary test used, and the anchor depth mixes the two regimes smoothly - implemented IDENTICALLY in the march and the gather (the two stages must agree on where a probe sits, or the LOS check desynchronizes from the field). Lesson recorded: per-cell classification heuristics need continuity across cell boundaries; anything a bilinear sampler interpolates must itself be continuous.
44. **Point-light shadow rays overshot the light and hit whatever sat behind it.** The shadow-ray bound for a point light was the light's RADIUS cutoff (or 60 m), not the distance to the light: a wall point half a metre from a lamp traced metres PAST the light and treated the ceiling behind it as an occluder, carving phantom shadow disks around every nearby light - looping bright/dark bands on the wall and ceiling around the demo's fill light (isolated by toggling relight shadows and the reflection pass separately; the loops followed the light's position, not any geometry). Fix: `maxDistance = distance(light, point) - 0.05` in both consumers (`pbr_lighting.comp` pointContribution and `lighting_common.glsl` pointDiffuse). Lesson recorded: a point light is not geometry - a shadow ray must terminate AT the light, and a radius cutoff is a contribution gate, never a ray bound.
45. **Normal-mapped shadow origins started inside the analytic geometry.** The direct pass offset its shadow rays by the G-buffer normal, which carries the material's NORMAL MAP; on curved surfaces the tangent-heavy perturbation pushed the start point inside the SDF, where sphere tracing reports an immediate hit - black blocks speckled over exactly the curved, textured objects (the artifact appeared only once real normal maps shipped, problem 39's fix). Fix: check the SDF at the offset origin; when it is inside, re-offset along the SDF's own geometric normal (`sdfNormal`), which is exact at the surface. The GI gather and the march already had the same guard. Lesson recorded: a perturbed shading normal is a shading input, not a safe ray origin - every ray leaving a normal-mapped surface needs an inside test with a geometric fallback.
46. **The sun was drawn twice on glossy pixels.** The pbr pass rendered the full analytic GGX specular AND the ray_reflections layer pre-multiplied its mirrored content (including the sun disk) by the same Fresnel energy; the composite adds both, so a mirror ball showed two suns and grazing specular energy roughly doubled. Fix: a specular SPLIT - when ray_reflections is configured, the pbr pass dims its analytic specular per pixel by `1 - w`, with `w` the SAME weight the reflection pass uses (identical Schlick-with-roughness Fresnel and the shared `pow(1 - roughness/max, 1.5)` fade), so the two layers partition the specular energy and the hand-over is continuous at the reflection pass's weight threshold. Lesson recorded: two passes writing one energy channel need an explicit partition contract, expressed as the same formula in both shaders and one config key (`[lighting.ray_reflections].max_roughness`) both read.
47. **Interactive runs starved the OS message pump ("not responding").** The shipped demo configuration combined `enable_validation = true` (a large CPU tax on every dispatch) with `probe_stride = 2` at 720p (29 million march invocations per frame) plus radius-8 bilateral filtering: multi-second frames on mid hardware, and the host loop polls window events only between frames - Windows marks the window "not responding" within seconds. Fix: configuration, not code - the interactive `config/engine.toml` runs with validation off (the automated smoke and leak configs keep it on) and the GI balance moved to `probe_stride = 8`, `los_steps = 16`, `march_steps = 48`, filter radius 10, a 16x cheaper march with smoothness carried by the LOS-guarded gather, the continuous cascade blend and the spatial filter; the cost model is documented in the config comments. Lesson recorded: frame cost is a message-pump contract - the host loop's event poll rate equals the frame rate, so every shipped configuration must keep frame time far below the OS's hang detection window (about 5 s), and the heaviest quality knobs belong behind documented, per-machine configuration.
48. **The reflection pass silently lost its lights to the permission system.** `ray_reflections` acquires the `lighting` capability through a try/catch that treats `ComponentAccessError` as "provider absent" - but the error also fires when the component lacks the `capability.lighting` PERMISSION, which its manifest never declared (radiance_cascades declares it; ray_reflections was written without it). Every reflection thus rendered from a zeroed light uniform: the mirror ball showed only emissive hits and the screen-space GI reuse term - a matte-brown ball with no room, no sun, no window - while the direct pass one module over rendered the same lights perfectly. Found by channel-isolating the reflection shader (relight vs GI-reuse vs sky), then probing the uniform's point-light count inside the dispatch, then logging the acquisition: `lighting capability ABSENT` printed before the provider module had even constructed. Fix: declare `capability.lighting` in `requiredPermissions` (the capability stays optional at acquire time - a genuinely absent provider still degrades to emissive + sky), and the QA diagnostic log line stays: it names which failure mode fired at startup. Lesson recorded: an optional capability needs its permission declared anyway, and a catch that swallows an acquisition error must distinguish "absent" from "denied" - both crash nothing, and one of them blanks a whole rendering layer.
49. **Reflection rays re-hit their own launch surface.** The reflection ray starts 1 cm above the G-buffer surface, but `traceInterval` begins at t = 0.02 with no self-hit guard (the cascade march has one; the reflection pass was written without it): rays leaving a convex surface near the silhouette re-hit that same surface a few centimetres out, and the pass relit the LAUNCHER - the glossy sphere reflected its own shadowed underside as a dark self-image ring, and mirror-ball silhouette pixels showed the ball instead of the room. Fix: hits closer than 3 cm are rejected as self-hits and fall back to the open-reflection sky path; a genuine target sits farther than that from a launch pad that already carries one centimetre of clearance. Lesson recorded: every sphere-tracing consumer needs the same three guards - origin clearance, grazing self-hit rejection, interval bounding - and copying them per-consumer (not sharing a helper) guarantees one gets forgotten.
50. **The gather's grazing band collapsed into black per-probe blobs.** For pixels on a surface seen at a steep angle, the screen-space probe neighbours anchor ACROSS the object's own silhouette; the line-of-sight segment exits through the object itself, every probe drops, coverage hits zero for both the selected cascade AND the cascade-0 rescue, and the starved-pixel fallback (the pixel's own direct light - near zero on a shadowed face) painted soft black blobs in a periodic per-probe pattern down the box face (isolated with a coverage visualization: the blobs were exactly the coverage = 0 cells). Fix: same-surface trust in the gather - a probe whose anchor sits within 0.8 m with agreeing normals is kept when the midpoint of the visibility segment reads positive in the SDF: two points of one surface have their midpoint ~1 cm outside it, a probe across a solid wall puts the midpoint INSIDE the wall (full LOS test runs, probe stays blocked, leak guarantee unchanged), and a probe across a window opening carries a near-identical field anyway. Lesson recorded: a visibility guard is only as good as its failure mode - coverage collapse must degrade to the next-best LOS-guarded estimate, never to black, and same-surface pairs are the one occlusion case the segment test answers wrongly.
51. **The demo scene's energy balance flooded the room.** Emissive panel radiance 14, point lights 12 and 8, exposure 1.5: the ceiling around the panel clipped to flat white across its whole span, the mirror ball reflected a blown-out room as a white blob, and the direct pools clipped in the ACES shoulder (the numbers are radiance and inverse-square intensities, so a 1.6 x 1.6 m panel at 14 dominates every other source by an order of magnitude). Fix: configuration rebalance - panel 3.5, point lights 6.0 / 3.5, exposure 1.15 - with the reasoning documented in `config/engine.toml` comments; the panel is again the brightest element with visible falloff, walls keep gradation, and the mirror shows the room instead of a white wash. Lesson recorded: physically-scaled light values need a shipped-scene sanity pass - render the four QA poses and check the histogram before committing an energy change, because every term is correct and the SUM can still be flat white.
52. **The gather's leak guard was dead code - a shadowed variable discarded every visibility result.** Inside the probe loop, the guard block re-declared `float visibility;` locally, SHADOWING the initialized outer variable: both branches computed the line-of-sight result, the inner binding died at the end of the block, and the blend kept the outer `1.0` - NO probe was ever dropped, the gather bilinearly bled radiance across every wall silhouette at the probe grid's scale (the persistent blocky leaks the visibility work was supposed to remove), the starved-pixel fallback never engaged (coverage never dropped below 1), and none of it crashed or tripped validation. The leak check missed it because its sealed probe sits deep inside thick geometry, beyond the grid-scale bleed the dead guard would have prevented. Fix: assign the outer variable; the guard's documented contract (smooth drop near silhouettes, exact zero for deep occlusion) holds again. Lesson recorded: a guard whose result is computed and then thrown away is worse than no guard - it reads correct in every review that checks "is there a visibility test?" without executing it; shadowing warnings are not enabled for GLSL, so the leak check's regions must include one NEAR a silhouette, not only one deep behind a wall.
53. **The analytic SDF rotated boxes the wrong way - traced geometry was a mirrored ghost of the rasterized geometry.** `sceneSDF` and the relight's material lookup converted world points to primitive-local space with `rotateY(delta, +radians)`, but that is the LOCAL-TO-WORLD rotation the model matrix applies; the inverse needs `-radians`. Every rotated primitive was traced as a box standing at `-rotationY` around its centre while the G-buffer showed it at `+rotationY`: shadows cast from the wrong silhouette, GI occluded by the wrong shape (dark patches and leaks around the object), reflection rays hitting empty air where the object visibly stood, and material UVs drifting across a 2x rotation seam on every GI bounce and reflection hit. With `rotation_y = 0` (the sealed leak-test room, the QA room's walls) both directions agree, so every automated test stayed green. Fix: a `worldToLocalY` helper (the inverse rotation) used at all three world-to-local call sites; verified offline by evaluating the SDF at the rotated box's rasterized face centres and corners (all read 0.0000). Lesson recorded: a mesh and a distance field that must agree under rotation share NO test at rotation 0 - one QA object must carry a nonzero rotation, and an offline replication of the shader math is the cheapest possible guard for transform conventions.
54. **Technique passes raced each other on the same command buffer.** The renderer records the attached lighting techniques back-to-back with no ordering of its own; `ray_reflections` samples the cascade denoiser's indirect-radiance target (its GI reuse term) - a compute-write to compute-read pair inside ONE command buffer, which is unordered and invisible without a memory dependency: the reflection pass sampled stale or garbage GI (nondeterministic reflections that could shift every frame). Fix: the renderer emits a global compute-to-compute memory barrier (shader-storage-write to shader-read) before every technique record except the first. Lesson recorded: pass composition is a synchronization contract - the compositor owns the barriers between consumers, exactly as it owns the G-buffer hand-off; a technique interface that records into a shared command buffer must document the insertion points where the compositor barriers on its behalf.
55. **The frame-start hazard barrier's destination scope missed compute writes.** The barrier that orders the previous frame's reads against this frame's writes declared `color attachment output` as its destination stage - correct for the G-buffer attachments, but the radiance targets are written by COMPUTE storage operations: with two frames in flight, frame N+1's lighting dispatches could clobber the indirect image while frame N's composite fragments were still sampling it (sporadic stale-GI frames, driver-dependent). Fix: the barrier's source scope covers all commands and reads, the destination all commands and memory writes. Found by re-auditing the frame graph with sync2 scopes, not by a failure - the class is invisible on software WSI (problem 22's family). Lesson recorded: a "frame-start" barrier must enumerate the write STYLES of the new frame (attachment writes and storage writes), not just the first one.
56. **The GI denoiser's depth band was measured in NDC units.** The bilateral filter's depth weight compared raw buffer depths against a fixed fraction of the center depth: the projection's hyperbola makes one milli-NDC a hair's breadth near the camera and metres far away, so the band held edges close to the camera and widened to multiple metres at mid range - the filter happily averaged GI across distant parallel surfaces whose normals agree (a wall in front of a wall, boxes in front of the back wall), which read as far-field blocky bleed riding exactly those pairs. Fix: the filter linearizes buffer depth with the camera's near/far planes (new `FrameRenderContext` fields, carried in the filter's push constants) and measures the band as a percentage of VIEW depth - one edge-awareness metric for the whole frame. Lesson recorded: any threshold compared against buffer depth is implicitly a curve in world space; linearize first, then choose the threshold in the unit the artifact lives in.
57. **Reflection rays launched from inside the geometry, and grazing self-hits survived the fixed guard.** Two related defects on the metal sphere: (a) the launch origin was offset by the G-buffer normal, which carries the material's normal map - the same inside-origin hazard problems 39/45 fixed for shadow and LOS rays, missing here, so sphere tracing started inside a solid, reported a bogus immediate hit, and the pixel reflected the sky (dark sky-coloured patches on curved, textured mirrors); (b) the fixed 3 cm self-hit guard only rejected hits CLOSE to the launcher - grazing rays re-hitting the ball 5-30 cm out passed the guard and painted a dark speckle ring around the mirror ball's rim. Fix: (a) the same inside-test discipline as the other consumers (geometric-normal fallback, then the always-outside camera direction); (b) convex self-hit RESOLUTION - every scene primitive is convex, so a reflection ray can never legitimately return to its launch primitive; hits whose owner primitive equals the launch point's owner are skipped past (the march restarts just beyond them, budget bounded) instead of discarding the whole reflection. The shared nearest-primitive lookup moved into `primitiveOwnerAt` so the relight and the owner test cannot drift. Lesson recorded: problem 49's "three guards per sphere-tracing consumer" list needs a fourth - an owner comparison turns self-hits from a special case into a restart, and the fixed-distance variant of it is guaranteed to be wrong at SOME grazing angle.
58. **Two frames in flight raced every shared GPU resource - the reported interactive flicker.** All transient targets (G-buffer, radiance layers, cascade fields) and the host-written uniforms (camera, environment, technique light states) are single-buffered and shared by every frame slot, and nothing ordered consecutive frames against each other: frame N+1's G-buffer writes could overlap frame N's gather reads, and the per-frame camera memcpy could land mid-frame - torn matrices, clobbered indirect light; stable on software renderers and flickering on real ones (lavapipe executes submissions synchronously on the calling thread, so the static-frame probe showed byte-identical frames while the race existed by spec). The frame-start barrier does NOT cover this: a barrier's synchronization scope never crosses a queue submission boundary - only semaphores or fences order submissions. Fix: host-side full frame serialization - every drawFrame waits for BOTH in-flight fences before updating any host-mapped uniform or recording commands, so at most one frame executes at a time; with every pass reading the shared targets, overlapped execution carried no throughput benefit, and the cost is CPU recording overlap (microseconds against multi-millisecond GPU frames). `max_frames_in_flight` now decouples command buffers and swapchain acquisition, not GPU execution - documented in the config and in docs/architecture.md. Verification: an 8-frame consecutive-capture probe (`scripts/qa_flicker_run.sh`, one capture per frame through the new `engine.subscribe_frame_begin` scripting bridge) diffs every consecutive pair - byte-identical on the static scene. Lesson recorded: single-buffered targets and frames-in-flight > 1 are contradictory claims; pick one, and pick the fence when the harness cannot observe the race (problem 22's family).
59. **Script mods could never request screenshots - the capability was resolved before it existed.** `lua_scripting` requires only `logging` and `window`, so the kernel's topological construct order placed it BEFORE the screenshot module (which waits on `renderer`) had registered its capability; the construct-time `acquireCapability<ScreenshotCapability>()` threw, the catch cached "unavailable" forever, and every `engine.request_screenshot()` call - the example mod's F11 path included - logged "screenshot module is not part of this build" while the module demonstrably ran. The automated runs never noticed because the HOST queues its own capture through the same capability at smoke-run half-time; the Lua path was silently dead in every configuration. Fix: optional capabilities resolve lazily at first CALL time (inside the frame loop, after every component has constructed), with a tri-state cache so a genuinely absent module still warns only once. Lesson recorded: acquiring an OPTIONAL capability at construct time is an ordering bet on the resolver's tie-breaking; resolve-at-use with a cached verdict is order-proof, and "the provider demonstrably started" is exactly the trap that hides the failure.

## How runtime regressions are caught

The Catch2 suite deliberately stays headless: it never opens a window or creates a Vulkan instance. That leaves the real rendering path unverified by unit tests, which is exactly how problems 18 to 21 slipped through: every one of them lived outside unit-test reach. The headless smoke test closes that layer.

`ctest` runs three test tiers:

- `engine_tests`: the kernel and module unit tests (59 cases, including the fly camera controller binding and the frame-sync ownership model).
- `engine_headless_smoke`: boots the assembled runtime — logging, window, input, renderer, lighting modules, screenshot, both example mods — renders 30 frames of the 3D scene on a virtual display (the script starts its own Xvfb when no display is set) with `config/smoke.toml` (small resolution, reduced GI cost), queues one screenshot halfway through so the full capture path runs, and fails on any crash, thrown exception or graphics backend validation error. The exit code comes from the renderer's own validation-error observation (contract method `validationErrorsObserved`), not from scraping logs.
- `engine_leak_check`: the automated light-leak test. `config/leak_test.toml` builds a sealed room with a point light and an emissive panel inside and one window opening; the engine's own `--leak-check` evaluates the captured frame against the configured regions and exits 4 on a light leak (radiance behind the sealed wall) or a dead GI path (dark window view). This is the standing guard for the radiance cascades' no-light-leak guarantee, and it is sensitive enough that the self-intersection bug (problem 23) turned the whole frame black instead of passing.

The smoke run needs a Vulkan ICD and runs against whatever the machine provides: a real GPU driver on developer machines, Mesa lavapipe in a container. Validation layers turn every VUID violation into a test failure, so the smoke proves spec conformance of the rendering path, not driver-specific behavior. Manual equivalent: `engine --smoke-frames 30` (see `docs/building.md`).

**The smoke run has two known blind spots, demonstrated by problems 22 and 25.** First, synchronization races that depend on presentation depth: software WSI (lavapipe) completes present operations synchronously, so a swapchain semaphore reused one frame too early is always legal *there* - the buggy build passed a 60-frame smoke run while the same code flooded a real NVIDIA/Windows driver with `VUID-vkQueueSubmit-pSignalSemaphores-00067`. The deterministic guard for that class is the frame-sync ownership test (`tests/frame_sync_policy_tests.cpp`): it replays the acquisition sequences recorded in the field report against the production `FrameSyncPolicy` and proves both that the policy never re-signals a semaphore whose presented image has not been re-acquired and that the historical per-frame ownership does violate the same sequences - so reverting the ownership model fails the suite on any machine, driver or none. Second, object-lifetime tracking differences between validation layer builds (problem 25): a descriptor set layout destroyed under a live pipeline is reported on NVIDIA's layer and silently accepted on the sandbox's - the guard there is the structural rule (reverse-dependency teardown, members not locals) documented in problem 25 and `docs/architecture.md`, section Conventions.

## Known limits

- Script permissions are checked at startup and at subscription time; per-call re-checking inside the Lua bridge is planned.
- Mod manifests do not yet carry version ranges for `requires` entries (the engine mod ABI version is checked).
- The event bus is single threaded by contract; queued delivery would be a separate module.
- The smoke run exercises acquire, record, submit, present, capture and clean shutdown, but not interactive window resizing; swapchain recreation is covered by the `eOutOfDate`/`eSuboptimal` handling and the format-change pipeline rebuild, and can be verified manually on a desktop.
- The smoke run proves validation-layer conformance on the available ICD (lavapipe in CI-like environments); it does not replace a run on real vendor drivers, which is why `--smoke-frames` exists on every machine.
- Presentation-depth-dependent synchronization races (problem 22's class) are invisible to the smoke run on software WSI; they are covered deterministically by the frame-sync ownership test instead. Any future synchronization change to the frame loop must extend that test with the new ownership invariants, not only the smoke run.
- The leak check runs at reduced GI settings on software rasterizers; a real-GPU run with quality settings (`probe_stride = 4`, higher `base_rays`) remains the visual reference. Emissive-surface GI quality scales with `base_rays` (problem 24); point and sun lights are exact at any setting.
- The gather's probe-visibility blend is continuous near silhouettes (a ray-length-scaled transition band) instead of strictly binary; deep occlusion is still exactly zero, and the sealed-room leak check enforces the no-leak property on every run. Small bright emitters remain angular-resolution limited: visible banding around a point-sized panel is a `base_rays` quality tradeoff, not a leak.
- Probe starvation fallbacks are continuous (the finer cascade, then cascade 0, then the pixel's own direct radiance, blended over the coverage collapse) but they remain quality approximations: a faint bright trace can remain hugging an object's contact silhouette where the coarse cascade's coverage collapses, softened further by `spatial_filter`. The no-leak property is unaffected (every fallback is line-of-sight guarded, and the same-surface trust of problem 50 still routes anything whose segment midpoint reads inside geometry through the full test).
- Reflections are one ray traced bounce with screen-space GI reuse: a reflection hit carries the textured direct relight plus the composed diffuse GI only where the hit point reprojects into the frame with a matching depth; reflection hits outside the reuse window show direct + emissive + sky but no indirect fill, and rougher-than-`max_roughness` surfaces get no reflection at all (a single sharp ray cannot represent a wide glossy lobe without temporal accumulation). Grazing self-hits are skipped past (the march restarts beyond them, problem 57): a convex launcher can never legitimately reflect onto itself, so the pixel keeps reflecting the room behind it instead of speckling self-images or falling back to the sky path.
- Normal maps do not perturb the SDF relight (GI bounces and reflection hits use the geometric normal); the primary surface's shading is fully normal-mapped through the G-buffer.
- Compute passes sample the texture arrays at LOD 0 while the geometry pass uses the mip chain; GI bounce colors are therefore slightly sharper than the camera-surface shading at grazing angles.
- All texture sets used by one scene must share one resolution (the arrays are uniform); a mismatch fails startup with a precise message.
- Scene geometry is fixed at startup: `[scene]` is parsed once and uploaded once. Runtime geometry changes (moving objects, dynamic meshes) are future work; runtime light changes through the `LightingCapability` are supported every frame.
