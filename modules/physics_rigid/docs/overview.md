# physics_rigid module

physics_rigid provides deterministic double-precision rigid body simulation: static, dynamic, and kinematic bodies with sphere, box, capsule, cylinder, and plane shapes; a spatial-hash broadphase; a warm-started sequential impulse solver for contacts and joints; speculative contacts with optional per-body continuous collision sweeps; island-based sleeping; trigger volumes that report which bodies enter or leave designated regions through a polled event queue; and the query surface (ray casts, sphere sweeps, deepest sphere overlap, mass properties, statistics) that other simulation modules and applications build on. The module owns no rendering state; consumers read body states and feed them to their own presentation layer.

## Capability

The module provides the `physics_rigid` capability (ABI version constant `physicsRigidCapabilityAbi = 6`; the header's ABI history comment records what each bump appended, the cylinder shape and the trigger-volume surface arrived in ABI 4, the batched query surface — `collideSpheres`, `copyBodyStates`, and `copyBodyDescriptions` with the `SphereOverlapQuery` / `SphereOverlapResult` records — arrived in ABI 5, and the simulation-LOD surface — `setBodyImportance` with the per-band solver iteration budgets and the `WorldStatistics.lodReducedBodyCount` counter — arrived in ABI 6; consumers check `abi >= 6` before touching those additions, while everything from ABI 5 keeps its slot and meaning). World, body, joint, and trigger handles are `std::uint32_t`, start at 1, are never reused, and `0` (`invalidWorld` / `invalidBody` / `invalidJoint` / `invalidTrigger`) means "none". All positions, extents, and velocities are in meters, seconds, and radians; transforms are position plus an x/y/z/w quaternion.

### Frame-rate independence contract

The world advances in whole fixed steps only. `step(world, fixedDeltaSeconds)` performs exactly one step and must be called with a constant delta across a running simulation (values in (0, 0.1] are accepted; anything else is rejected). A delta above the configured `substep_maximum_delta` (1/120 seconds by default) is split into equal internal substeps, so a consumer that steps at 30 or 60 Hz integrates through the same canonical passes as one stepping at 120 Hz — identical inputs produce identical results at any of those rates, which the demo's self-test verifies. `simulate(world, elapsedSeconds)` is the accumulator variant: it adds elapsed wall time to the world's budget, runs whole fixed steps at the configured `fixed_rate_hz`, and drops backlog beyond `maximum_steps_per_simulate`, so a stalled consumer can never spiral. Application loops that follow the engine's FrameClock (fixed update count plus interpolation alpha) call `step` once per fixed update and render with interpolated transforms; the simulation result then depends only on the step count, not on how frames were paced.

**Error convention:** functions returning `bool` fail on unknown handles or null outputs; creation functions also fill the `PhysicsError` out-parameter (`InvalidDescription`, `CapacityExceeded`, `Unsupported`, `SimulationFailure`). A `SimulationFailure` restores the pre-step state: when any body enters a non-finite state during a step, the whole step is rolled back and reported instead of propagating NaNs.

## How it works

**Bodies and shapes.** `createBody` validates the shape (positive extents, finite values, planes static-only), normalizes the rotation, derives mass properties, and stores the body in the world's dense array with a monotonic handle. Density above zero multiplies the exact shape volume (sphere, box, solid capsule, or solid cylinder); otherwise the explicit mass is used with the shape-derived principal-axis inertia. Sphere, box, capsule, and cylinder inertia are the closed-form formulas about the shape's local axes; the world-frame inverse inertia is reconstructed per solve as `R diag(1/I) R^T`. Static and kinematic bodies carry zero inverse mass; kinematic bodies integrate their velocities every step but ignore forces, and both kinds push dynamic bodies through contacts without being pushed. `setBodyKind` re-derives the mass properties from the stored mass source, so a body can be promoted from static scenery into a dynamic actor (and back) without recreating it.

**Collision pipeline.** Every step, the broadphase inserts each solid body's world-space AABB into a uniform spatial hash keyed by the configured `spatial_hash_cell_size`; dynamic and kinematic bodies probe their own cells for candidates. Cell coordinates beyond the representable range clamp to the boundary cells and the three coordinate lanes mix into one 64-bit key, so a key collision only merges candidate buckets (the AABB test still rejects outsiders deterministically). Candidate pairs are deduplicated by an unordered index pair, rejected when both bodies are static, both sleeping, or mutually excluded by the category/mask filter, then AABB-tested, and the survivors are sorted by dense index so narrowphase and the solver see a deterministic order. Planes are unbounded and never hashed: every awake non-static solid body is tested against every plane directly and merged into the same manifold store with canonical pair ordering, with a cheap velocity-extended AABB rejection in front of the shape test so bodies far from a plane skip its full narrowphase. Narrowphase dispatches per pair shape combination within the configured `contact_margin`: sphere tests are analytic; box pairs run a full 15-axis separating-axis test with reference-face clipping against the incident face polygon (up to four points, edge axes preferred only when they beat the best face axis by more than five percent so stacks rest on face contacts); capsules contribute segment-swept sphere tests (two interior samples against boxes, exact closest-segment for capsule pairs); planes clip box corners and sample capsule endpoints. Separations may be positive up to the margin (speculative contacts), which keeps resting manifolds alive instead of detaching and re-impacting every step.

**Cylinders.** Cylinder shapes run along local +Y with a radius and half-height, carrying the closed-form solid-cylinder inertia and an exact support-function AABB (the half-height projected on each world axis plus the cap-disc radius in the perpendicular plane). Sphere pairs solve analytically against the closest point on the solid (with the same nearest-surface escape the box uses inside); capsule pairs test the capsule's two interior spheres; box and cylinder pairs project a fixed set of surface samples (the box's eight corners, ten cylinder samples — two cap centers and four rim points per cap at fixed quarter angles) onto the other solid, letting the deepest contact's normal lead a manifold that stacks rest on; plane contacts sample the same ten points so an upright cylinder rests on four rim contacts the way a box rests on four corners; ray casts solve the side-surface quadratic plus both cap discs, and sphere sweeps run against the cylinder inflated by the query radius (side band, cap discs, rounded rim spheres). The fixed sample sets and the deterministic disc basis keep every result reproducible.

**Manifolds and warm starting.** Narrowphase results land in persistent manifolds keyed by the unordered body-handle pair. Fresh points match persisted points by anchor proximity and inherit their accumulated normal and tangent impulses plus the tangent basis they were accumulated along, so a resting stack starts each step from the previous solution instead of re-converging from zero. Manifolds that narrowphase did not refresh are dropped the same step. After the final solve iteration the current tangent basis is written back into the persisted points so the next step's warm start applies impulses in the same frame.

**Canonical substepping.** `stepWorld` validates the delta, splits it into `ceil(delta / substep_maximum_delta)` equal internal passes (capped at 16), and runs the pipeline once per pass. Every pass re-runs broadphase, narrowphase, solving, and integration on the shared state, so warm starting carries across passes and the sleeping timers accumulate real time. The split count depends only on the delta and the configured target, which keeps coarse-rate callers bit-identical to fine-rate callers over the same wall-clock span.

**Solving.** Constraints solve in fixed order: contacts sorted by pair key, then joints in creation order, iterated up to `solver_velocity_iterations` times per step — each constraint carries its simulation-LOD iteration budget and drops out of the passes once the budget is spent. Each contact point runs a block solve: the normal row targets restitution (applied only to approach speeds beyond `restitution_velocity_threshold`) plus the speculative gap - a positive separation must close within the step, which stops approaching bodies before they touch and removes impact overshoot; the accumulated impulse may never open a speculative gap faster than the gap allows. Two tangent rows follow, clamped to the Coulomb cone `friction x accumulated normal impulse` with the pair coefficient `sqrt(fA x fB)`, and a rolling-resistance row per tangent axis damps the relative spin about that axis within a budget of `coefficient x normal impulse x contact radius` (the larger body coefficient wins; only curved shapes carry a rolling radius), so the torque scales with the load the way physical rolling resistance does and never injects energy. Joints contribute: distance rows along the current anchor separation (with the soft spring form when `setJointSpring` configures frequency and damping); ball-socket rows as three anchor-coincidence components on an anchor-derived orthonormal basis; hinge rows as the same anchor rows plus two anti-swing angular rows that drive the measured swing tilt back to zero; prismatic rows as two perpendicular anchor rows, the anti-swing pair, a twist lock, translation limits, and a linear motor along the axis; and fixed weld rows as three anchor components plus three angular rows holding the frame captured at creation. Angle limits (hinge range, ball-socket swing cone and twist range, prismatic travel) are one-sided boundary rows that resist further violation; their impulses are recomputed from scratch every step instead of warm starting, which keeps chattering joints from accumulating stale boundary impulses. The hinge motor tracks a target angular velocity about the hinge axis within a torque budget, and the prismatic motor tracks a target sliding velocity within a force budget. All accumulated impulses live in the world-owned joint and manifold records, which is what makes warm starting exact across steps for the continuous rows.

**Continuous collision detection.** Bodies flagged through `setBodyContinuousCollision` (or `BodyDescription.continuousCollisionEnabled` at creation) whose speed exceeds `ccd_velocity_threshold` are swept each step from their pre-integration transform to the integrated one: a bounding-sphere proxy casts against every static and kinematic solid body and plane, and a hit clamps the integration at the contact minus the speculative margin while cancelling the approach speed with the body's restitution, so fast movers tunnel-proof through thin walls without paying sweep cost on slow bodies.

**Position solving.** After the velocity iterations, `solver_position_iterations` passes move the transforms directly to remove the remaining contact penetration: each contact point whose separation exceeds `contact_slop` applies a positional displacement (`position_correction_factor` of the error, clamped by `maximum_linear_correction`) along the contact normal through the point's mass matrix. Splitting position repair from the velocity solve means penetration leaves without injecting the bounce energy a bias velocity would, so stacks settle instead of oscillating.

**Sleeping.** After integration, islands are formed over the contact and joint graphs (union-find over dynamic bodies). An island whose dynamic members all stay below the linear and angular sleep tolerances accumulates sleep time; once it passes `time_to_sleep` every member sleeps (velocities zeroed, broadphase skipped for sleeping-sleeping pairs). Any island motion above tolerance resets timers and wakes the island, so a body nudged by a falling object or an opened joint drive rejoins the simulation immediately. Kinematic and static bodies never sleep and never block an island from sleeping.

**Simulation LOD.** Sleeping removes islands that stopped moving; the fidelity ladder scales the work that keeps moving. Every dynamic body carries an importance score (`setBodyImportance`, default 1.0) that resolves once per step onto the five shared bands — Cached, Animation, Procedural, Simplified, Full — with demotion hysteresis, and each band maps to a velocity and a position iteration budget (`lod_velocity_iterations` / `lod_position_iterations`; by default Full keeps the configured counts and each lower band halves them, floored at one). A constraint's budget is the largest budget among its dynamic bodies, so an important body resting on a reduced-fidelity pile still solves at full quality while a distant pile on the static ground solves at its own band. Warm starting carries the previous solution into the reduced passes, which is what lets a far stack hold its pose on a fraction of the iterations. The fixed step, the integration, and the collision pipeline never change: a LOD-reduced body moves through exactly the same world as a full one, only its constraints converge less deeply per step. `worldStatistics.lodReducedBodyCount` reports the awake dynamic bodies below Full on the last step, and with `lod_enabled` off (or every score at 1.0) the solver runs exactly as before the ladder existed.

**Trigger volumes.** A trigger is a non-solid shape region (any solid shape; planes are rejected) evaluated once per substep against the world's solid bodies after integration: the broadphase-level AABB precheck is followed by the same narrowphase overlap test at zero margin, so touching counts as inside. Each trigger keeps its overlap set sorted by body handle and diffs it against the previous set in one linear walk, producing `Enter` and `Exit` events in trigger-creation order and body-handle order; events accumulate in a per-world queue bounded by `maximum_trigger_events` (the oldest event is dropped with the overflow flag once the bound is exceeded) and drain through `triggerEventCount` / `copyTriggerEvents` / `clearTriggerEvents`. A trigger either sits fixed in the world or attaches to a body and follows that body's transform composed with a local offset pose every evaluation; a destroyed body reports exits from every trigger it overlapped and dies together with its attached triggers, and a destroyed trigger drops its own pending events. Transform entry points reject non-finite positions and rotations up front, so a NaN pose can never reach a body record or hand NaN back to a consumer. Disabled triggers emit exits for their current set and stop evaluating; sleeping dynamic bodies stay overlapped until they separate. Triggers never enter the broadphase or the solver, so their cost is one overlap test per (trigger, body) pair per step.

**Queries.** `rayCast` walks every body and plane with per-shape analytic tests (sphere quadratic, box slab test in local space, capsule as the minimum over both caps and the clipped cylinder surface, cylinder as the clipped side quadratic plus both cap discs, plane half-space) and reports the closest hit with the surface normal opposing the ray; `rayCastIgnoring` runs the same walk while skipping a caller-supplied body list, so character controllers can probe the ground through their own limbs. `sphereCast` sweeps a sphere from start to start plus delta and reports the first contact (the SweepHit record carries the body, point, normal, and travelled distance), which powers grabbing and camera probes against swept volumes. `collideSphere` reports the deepest penetration over bodies and planes with the push-out direction for the query sphere; it is the collision entry point for consumers that resolve their own particles (for example the physics_cloth module). `worldStatistics` reports body counts per kind, awake and sleeping counts, the simulation-LOD reduced count, joint count, contact pair and point counts, the trigger and pending-event totals, the cumulative step count, and the previous step's cost in milliseconds.

## Batched queries and step cost

Consumers that resolve many spheres per step — particle pools, cloth and rope nodes, fluid particles — call `collideSpheres` once per world instead of once per sphere: each query resolves exactly as the single-sphere `collideSphere` does (deepest overlap against every body and plane, unit push-out normal, penetration depth, responsible body), written in input order, with the solid bodies pre-filtered through their exact world-space shape bounds before the narrow-phase test runs. The batched body reads `copyBodyStates` and `copyBodyDescriptions` fill per-handle arrays in one call per world with the same semantics as the per-body copies (static and kinematic bodies always read awake, since they never sleep); entries for unknown handles stay default-constructed and the return value counts the resolved entries.

Inside the step, the spatial-hash broadphase rebuilds its grid into module-owned scratch buffers: a flat array of (cell key, body index) entries sorted per step, so every cell's candidates form one contiguous run found by binary search, and the surviving pairs deduplicate through the same sort. Once the buffers have warmed up the broadphase runs without per-step allocations. The island-sleeping pass and the CCD snapshot likewise run through step-scratch vectors. The `maximum_substeps` key bounds how many canonical substeps one caller step may split into when `substep_maximum_delta` requests more than the bound, trading canonical-step size for a bounded pass count.

## Threading and lifetime

The module has no locks. Object creation and destruction, `stop()`, and the stepping functions must be serialized from one thread (the main or simulation thread). Read-only queries (`copyBodyState`, `rayCast`, `collideSphere`, `worldStatistics`) may run concurrently with each other while no object-lifecycle call or step is in flight. Records live in the world's dense arrays and die with the world: `destroyWorld` releases every body, joint, trigger, and manifold; `stop()` clears all worlds and resets the handle counters. Destroying a body destroys its joints and its attached triggers and drops every manifold that references it. Handles are monotonic and never reused, so a stale handle is rejected rather than aliasing a newer object.

A consumer drives one fixed update per FrameClock step and renders interpolated states:

```cpp
engine::physics_rigid::PhysicsRigidCapability &physics =
    context.acquireCapability<engine::physics_rigid::PhysicsRigidCapability>();
if (physics.abi != engine::physics_rigid::physicsRigidCapabilityAbi)
{
    return;
}
const engine::physics_rigid::WorldHandle world = physics.createWorld(physics.self, &description, nullptr);
for (std::uint32_t step = 0; step < timing.fixedUpdateCount; ++step)
{
    physics.step(physics.self, world, fixedDeltaSeconds);
}
```
