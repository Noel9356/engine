# renderer backends

How the two `RenderBackend` implementations differ internally. Both implement the same interface (source/backend/render_backend.hpp) and are chosen per renderer at `createRenderer` time (see overview.md, "Backend selection").

## Headless (software rasterizer)

- **Target:** the window surface itself. `endFrame` locks the surface pixels (`window::WindowCapability::lockSurfacePixels`) and row-copies the CPU framebuffer - or, with anti-aliasing active, averages each output pixel's supersample block (see `renderer.msaa_samples` in configuration.md); `deviceClass()` reports `DeviceClass::Cpu`.
- **Pipeline:** per draw, `prepareRasterization` frustum-culls the mesh's model-transformed bounding sphere, resolves textures to neutral stand-ins, and probes a spread of up to 64 triangles' winding against vertex normals (majority vote) to decide whether back-face culling is safe; the vote's outcome depends only on the mesh geometry, the sampled index list, and the sign of the model matrix determinant, so it is memoized per mesh and re-derived only when the transform mirrors or the index subset changes. Vertex transforms live in a persistent per-mesh cache: the world stage (model transform + normal matrix) is keyed on the model matrix and the draw kind, and the clip stage on whichever matrix produced clip, so a static model matrix under a static camera skips the vertex stage entirely and a camera move reprojects without re-running the model stage. The cache's total footprint is bounded by `[renderer] headless_transform_cache_mb` (least-recently-used entries evict when a new mesh does not fit; a mesh larger than the whole budget is not cached and keeps the direct per-vertex path). `rasterizeTriangles` then near-clips, projects, and scans triangles with perspective-correct interpolation, shading with the same Cook-Torrance model as `shaders/mesh.frag` (render_shared.hpp), followed by tone mapping and manual 1/2.2 gamma (UNORM target always).
- **LOD:** meshes at or above `[renderer] lod_min_triangles` triangles get index chains decimated by the strides of `[renderer] lod_strides` (default 4/16/64); `drawMesh` picks a chain by the mesh's angular size (scaled bounding radius / distance) against the cutoffs of `[renderer] lod_thresholds` (default 0.02/0.05/0.1/0.2, ascending).
- **Parallelism:** when a `TaskScheduler` is available and a draw has at least `[renderer] headless_parallel_triangle_threshold` triangles, the triangle range is split across workers; each worker depth-tests under a spin lock per `[renderer] headless_pixels_per_lock_group` pixel group. Vertex transformation is also parallelized for meshes of `[renderer] headless_parallel_transform_vertices` vertices (default 8192). With no scheduler everything is single-threaded.
- **Instancing:** `drawMeshInstances` loops `drawMesh`; each instance's model matrix keys its own transform-cache entry, so repeated frames amortize the vertex stage.
- **Overlay:** software rasterized straight into the color buffer with "over" alpha blending and per-command scissoring.
- **Anti-aliasing:** `renderer.msaa_samples` (default 4) maps to the smallest integer supersampling grid of {1x1, 2x1, 2x2, 4x2} holding at least the requested count. The rasterizers shade sample-space pixels unchanged (everything downstream already sizes from the framebuffer), and `endFrame` averages each block of encoded UNORM samples across worker row bands when the scheduler is available - the software counterpart of the Vulkan resolve, including for the fur path that blends post-tone-map in that same space. UI overlays scale their display-to-framebuffer mapping by the sample factors, so text stays crisp after the resolve. The shading cost scales with the sample count (4 samples = 4x shaded pixels); 1 reproduces the pixel-for-pixel legacy path.
- **Statistics:** pure CPU counters; `gpuTimingAvailable` is always false.

## Vulkan

- **Device:** `VulkanDeviceContext` builds instance + surface (Win32/Xlib, or `VK_EXT_headless_surface` when the window provides no native handles), scores physical devices (device class, then timestamp-capable queue; filtered by `[renderer] device`), requires a graphics+present queue family, and creates the logical device with swapchain + optional memory-budget + optional conservative-rasterization extensions and anisotropy enabled. VMA owns allocations; `DeviceProfile` is snapshotted for consumers.
- **Frames:** `VulkanFrameScheduler` owns `[renderer] max_frames_in_flight` slots (command pool/buffer, image-available semaphore, in-flight fence - created signaled) plus the timestamp query pool when `[renderer] gpu_timestamps_enabled` and the device supports timestamps. Every submit waits the slot's previous work first, so recording never overtakes the GPU by more than the slot count.
- **Pipeline:** one PBR pipeline (44-byte per-vertex binding + 16-float per-instance binding, push constants, set 0 = frame uniform, set 1 = five combined image samplers, back-face culling and MSAA sample count baked in), one shell-fur pipeline (same vertex input and set layouts, 128-byte push constants, alpha blending with depth-write off - see `shaders/fur.vert`/`fur.frag`), and one overlay pipeline (no depth, src-alpha blending, 16-byte push constant). A disk-backed pipeline cache under the platform cache directory is loaded at build and saved at destroy. The SRGB_OUTPUT specialization constant (constant_id 6) is wired from `[renderer] srgb_output`; MAX_LIGHTS (constant_id 0) stays at 32.
- **Resources:** descriptor-pool capacity is reserved for one frame uniform set per in-flight frame, one neutral material set, and up to the configured material-set limit (five combined image samplers per material set). Device-local mesh buffers and texture images are uploaded through an asynchronous staging queue (one fenced one-shot command buffer per batch, capped by `[renderer] max_pending_uploads`); mip chains generated by linear blits. Material descriptor sets are interned per five-texture key; frame uniforms live in one persistently mapped buffer per slot, rewritten only when a revision counter says the camera/environment/lights changed.
- **Present:** presentation-queue policy comes from `[renderer] present_mode` (auto/fifo/mailbox/immediate, with `auto` falling back to the historical vsync-derived choice); per-image presentation semaphores; OUT_OF_DATE/SUBOPTIMAL mark the swapchain dirty and the next `beginFrame` recreates it (device idle, all objects rebuilt). PPM exports copy the acquired image through a host-visible readback buffer at `endFrame`.
- **Destruction:** during a frame it is deferred to a later frame slot (drained by `beginFrame`); outside a frame it waits for the device first.

## Behavior parity

The headless rasterizer exists so the engine renders identically (same formulas, clamps, and tone mapping) where Vulkan is unavailable; the deliberate coupling is documented in `shaders/mesh.frag` and `render_shared.hpp` - change one side and you must change the other. The shell-fur path follows the same contract: `shaders/fur.frag` mirrors `furShade`/`furAlpha`/`furStrandField` in `render_shared.hpp`, the fur vertex displacement mirrors `furDisplaceVertex` in `headless_backend.cpp`, and the headless fur commit blends AFTER tone map + gamma encode in the same space as the fur pipeline's fixed-function blending on the UNORM target (`drawFur` rasterizes sequentially, one pass per shell layer, depth-write off). Anti-aliasing is honored by both backends through `renderer.msaa_samples` (multisample resolve on Vulkan, supersampling resolve on headless). The lumen_reflection field composite runs in the headless rasterizer - the GLSL mirror would extend `mesh.frag` beyond the committed SPIR-V headers, so the Vulkan path consumes the module through its exported field (`copyField`) instead; the hook itself stays interface-complete on both backends. The transparent-draw pass (material `opacity` below 1: depth writes off, encoded-space alpha blend, and the traced-field transmissive composite where the reflection field carries a response) runs on the same headless-only scope; the Vulkan backend rasterizes every mesh opaque until its material pipeline grows the blend variant, and the shared `MeshMaterial` fields keep both sides ready for it. Features only the Vulkan backend has: instanced draws (the headless fur instance path loops `drawFur`), sRGB targets, GPU timing, pipeline cache, async uploads.
