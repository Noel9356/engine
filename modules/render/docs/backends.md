# render backends

How the two `RenderBackend` implementations differ internally. Both implement the same interface (source/render_backend.hpp) and are chosen per renderer at `createRenderer` time (see overview.md, "Backend selection").

## Headless (software rasterizer)

- **Target:** the window surface itself. `endFrame` locks the surface pixels (`window::WindowCapability::lockSurfacePixels`) and row-copies the CPU framebuffer; `deviceClass()` reports `DeviceClass::Cpu`.
- **Pipeline:** per draw, `prepareRasterization` frustum-culls the mesh's model-transformed bounding sphere, transforms vertices into a generation-stamped cache (bounded by `[render] headless_transform_cache_mb`; per-vertex cost is one transformed record plus a stamp), resolves textures to neutral stand-ins, and probes one triangle's winding against vertex normals to decide whether back-face culling is safe. `rasterizeTriangles` then near-clips, projects, and scans triangles with perspective-correct interpolation, shading with the same Cook-Torrance model as `shaders/mesh.frag` (render_shared.hpp), followed by tone mapping and manual 1/2.2 gamma (UNORM target always).
- **LOD:** large meshes get index chains decimated by keeping every 4th/16th/64th triangle; `drawMesh` picks a chain by the mesh's angular size (scaled bounding radius / distance) against four fixed thresholds (0.02/0.05/0.1/0.2).
- **Parallelism:** when a `TaskScheduler` is available and a draw has at least `[render] parallel_triangle_threshold` triangles, the triangle range is split across workers; each worker depth-tests under a spin lock per `[render] pixels_per_lock_group` pixel group. Vertex transformation is also parallelized for meshes of 8192+ vertices. With no scheduler everything is single-threaded.
- **Instancing:** `drawMeshInstances` loops `drawMesh`; the transform cache still amortizes the vertex shading.
- **Overlay:** software rasterized straight into the color buffer with "over" alpha blending and per-command scissoring.
- **Statistics:** pure CPU counters; `gpuTimingAvailable` is always false.

## Vulkan

- **Device:** `VulkanDeviceContext` builds instance + surface (Win32/Xlib, or `VK_EXT_headless_surface` when the window provides no native handles), scores physical devices (device class, then timestamp-capable queue; filtered by `[render] device`), requires a graphics+present queue family, and creates the logical device with swapchain + optional memory-budget + optional conservative-rasterization extensions and anisotropy enabled. VMA owns allocations; `DeviceProfile` is snapshotted for consumers.
- **Frames:** `VulkanFrameScheduler` owns `[render] max_frames_in_flight` slots (command pool/buffer, image-available semaphore, in-flight fence - created signaled) plus the timestamp query pool when `[render] gpu_timestamps_enabled` and the device supports timestamps. Every submit waits the slot's previous work first, so recording never overtakes the GPU by more than the slot count.
- **Pipeline:** one PBR pipeline (44-byte per-vertex binding + 16-float per-instance binding, push constants, set 0 = frame uniform, set 1 = five combined image samplers, back-face culling and MSAA sample count baked in) and one overlay pipeline (no depth, src-alpha blending, 16-byte push constant). A disk-backed pipeline cache under the platform cache directory is loaded at build and saved at destroy. The SRGB_OUTPUT specialization constant (constant_id 6) is wired from the (currently hard-coded) srgb setting; MAX_LIGHTS (constant_id 0) stays at 32.
- **Resources:** device-local mesh buffers and texture images uploaded through an asynchronous staging queue (one fenced one-shot command buffer per batch, capped by `[render] max_pending_uploads`); mip chains generated by linear blits. Material descriptor sets are interned per five-texture key; frame uniforms live in one persistently mapped buffer per slot, rewritten only when a revision counter says the camera/environment/lights changed.
- **Present:** FIFO vsync or mailbox/immediate without; per-image presentation semaphores; OUT_OF_DATE/SUBOPTIMAL mark the swapchain dirty and the next `beginFrame` recreates it (device idle, all objects rebuilt). PPM exports copy the acquired image through a host-visible readback buffer at `endFrame`.
- **Destruction:** during a frame it is deferred to a later frame slot (drained by `beginFrame`); outside a frame it waits for the device first.

## Behavior parity

The headless rasterizer exists so the engine renders identically (same formulas, clamps, and tone mapping) where Vulkan is unavailable; the deliberate coupling is documented in `shaders/mesh.frag` and `render_shared.hpp` - change one side and you must change the other. Features only the Vulkan backend has: instanced draws, MSAA, sRGB targets, GPU timing, pipeline cache, async uploads.
