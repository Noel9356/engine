# radiance_cache module

radiance_cache implements the engine's dynamic global illumination: a card-based **surface cache** of the scene, amortized direct and indirect lighting evaluated on the cached surfaces, a camera-centered **world-space radiance cache** of octahedral probes, and a **screen-space final gather** with temporal accumulation. The implementation is CPU-side (task-scheduler parallel) and traceable end to end; the renderer-facing result is the world probe grid exposed through `copyProbes`.

## Design provenance and documented adaptations

The stage structure adapts Epic's published Lumen design, which splits dynamic GI into: (1) a **surface cache** - an automatic parameterization of the nearby scene's surfaces into per-mesh "cards" (axis-aligned ortho projections) that store material properties and are relit every frame; (2) a **hybrid ray tracing pipeline** (screen traces first, then software distance-field or hardware ray tracing, skylight on miss) whose ray hits are shaded by looking up the surface cache; (3) the **final gather** - a Monte Carlo integration of first-bounce diffuse using a screen-space radiance cache backed by a world-space radiance cache for distant lighting; and (4) multi-bounce light transport through the surface cache itself, where each frame's texel gather samples the previous frame's indirect lighting and therefore propagates one more bounce per frame (N+2 bounces through feedback).

This module reproduces those stages on the CPU, with the following documented adaptations:

- **Card placement** uses Lumen's documented fallback projection: six axis-aligned face cards fitted to each surface's LOCAL bounds (so a moving instance carries its cache with it), subdivided when a face would exceed the per-axis texel budget; when the pieces exceed `cards.per_surface_max` (Lumen's default is 12 cards per mesh) the texel density is lowered instead of dropping pieces. Each card texel keeps up to `cards.depth_layers` front-facing hits, which stands in for Lumen's import-time surfel clustering on concave meshes (a room modelled as one mesh keeps its floor behind the ceiling's top face). The clustering itself is not implemented.
- **Ray tracing** runs against the registered triangle scene through a top-level BVH over the surfaces plus per-surface binned-SAH BVHs (rays transform into each surface's local space, so dynamic transforms only rebuild the small top-level tree) instead of building a separate tracing structure over card pages or distance fields. At CPU scene scales this is both faster to build and more accurate; shading at every hit still goes through the card surface cache exactly like Lumen's card lookup, which is the property that makes multi-bounce transport work.
- **Lighting propagation** follows Lumen exactly: direct lighting is evaluated into card texels under a per-frame texel budget (Lumen: 1024x1024 texels per frame), and the indirect gather is run in texture space against a second budget (Lumen: 512x512 texels per frame), sampling current direct and previous indirect radiance. Untouched texels keep their cached value, which is Lumen's "Lumen Scene Lighting Update Speed" behavior.
- **The world-space radiance cache** is a two-level camera-centered clipmap of octahedral probes (Lumen uses higher directional resolution - 32x32 - for world probes than for screen probes - 8x8) with toroidal scrolling: crossing a lattice cell recycles one plane of probes. Probes update on a per-frame budget, re-tracing a rotating stratum of their direction map with hysteresis blending; screen-probe rays are shortened and resolve their remainder from the world cache, which is Lumen's integration rule.
- **The final gather** exists in the module's debug view and runs on demand (when a view is exported) rather than every frame: screen probes on a jittered sub-resolution grid trace a few rays each, importance-sampled from the previous frame's probe radiance (Lumen's Screen Space Radiance Cache reuse), full-resolution pixels interpolate probe SH2 within their depth plane, then temporal accumulation and a bilateral spatial filter run - the same three tiers as Lumen's opaque Final Gather (screen cache, world cache, full-resolution interpolate/integrate/filter).
- **Contact AO, volumetric/fog GI, and translucency GI** are not implemented.
- Lumen itself is not compatible with forward shading; this module is. Where Lumen evaluates GI inside a deferred lighting pass, the engine's forward renderer consumes the exported probe grid instead (see the integration note at the bottom).

## Capability

The module provides the `radiance_cache` capability.

- ABI version: `4`, exposed as the standalone constant `radiance_cache::radianceCacheCapabilityAbi` (also the default of `RadianceCacheCapability::abi`)
- Header: `modules/radiance_cache/include/engine/radiance_cache/capabilities.hpp`
- Binding: `ParticipantContext::acquireCapability<RadianceCacheCapability>()`; every entry takes `capability.self` as its first argument.

| Entry | Purpose |
| --- | --- |
| `createSurface(self, desc, error)` | Registers one GI scene surface (borrowed geometry copied in; see `GiSurfaceDescription`). Returns a handle that is never reused; `0` means "none". |
| `updateSurface(self, handle, desc, error)` | Replaces geometry/material/transform of a surface; rebuilds its cards. |
| `updateSurfaceTransform(self, handle, transform)` | Fast per-frame transform path for `Dynamic` surfaces; a singular transform is refused and the previous one kept. |
| `destroySurface(self, handle)` | Removes a surface and rebuilds the card list. |
| `setView(self, viewProj, cameraPos)` | Camera for probe placement, capture priority, and the final gather. Required before `evaluate`. |
| `evaluate(self, deltaSeconds, error)` | Runs one GI frame on the task scheduler and blocks (the `render_graph::execute` pattern). |
| `copyProbes(self, out, capacity, outHeader, outVersion)` | Snapshot of the world probe grid (position + SH2 radiance + validity); a null/zero-capacity buffer still reports version and header for cheap change detection. |
| `statistics(self, outStats)` | Per-frame and cumulative counters (texels processed, rays traced, timing). |
| `resolveProfile(self, device, outProfile)` | Scales the amortization budgets for a `renderer::DeviceProfile`. |
| `debugExport(self, view, filePath, error)` | Writes one debug view as a binary PPM (`FinalImage`, `GiOnly`, `RadianceScene`, `SurfaceCache`, `ProbeIrradiance`, `Reference`). |

`evaluateProbeIrradiance` (and its core `evaluateSh2Irradiance`) are inline in the capability header so a renderer hook and the module agree on the probe representation: SH2 radiance convolved with the clamped-cosine lobe (Ramamoorthi), giving irradiance; a Lambertian BRDF turns it into outgoing radiance as `albedo / pi * irradiance`. The header also carries `probeTangentPlaneFactor`, the tangent-plane term of the probe interpolation weights the exported grid's consumers apply (a probe on the far side of the shaded point's tangent plane is down-weighted, the DDGI anti-leak rule), so the module's world cache, the renderer's probe walk, and `reflection_field`'s hit lighting all share one definition.

## Provided / required / optional capabilities

- **Provides:** `radiance_cache`
- **Requires:** none
- **Optional:** `pbr` (sun, hemispheric skylight, exposure, tone mapping) and `direct_lighting` (point/spot/directional lights). Without them the module uses the same built-in default environment as the renderer and no direct lights.

## How it works

**Frame evaluation (`evaluate`).** One mutex guards the registry; `evaluate` snapshots the environment (pbr version probe + `copyLights`), checks the static-frame skip, then runs one amortized frame (`runGiFrame`): plan and run incremental capture, finalize captured cards, plan the direct / indirect / probe work, then

```
capture -> direct -> caustics -> ( indirect | probes ) -> commit indirect
```

Each stage fans out over the scheduler with dynamic chunking and `evaluate` blocks until it finishes. The indirect stage reads only the committed cache and writes staging buffers that are committed afterwards, so concurrent traces never see a half-updated cache and texels outside the budget keep their value. The probe grid is published as an immutable snapshot, so `copyProbes` never waits for a running `evaluate`.

**Surface cache.** Each registered surface carries its geometry in local space plus a binned-SAH BVH. Its cards are axis-aligned face projections of the local bounds; capture casts ortho rays against the surface's own triangles (incremental and budgeted, nearest cards first) and stores albedo, local normal, and depth for up to `cards.depth_layers` front-facing hits per texel. A card is captured once and again only when its surface changes; moving a surface only marks its cached lighting stale. Lit points are the real surface points behind the card plane. Texels that find no front-facing surface keep the invalid depth and contribute nothing.

**Ray tracing.** A ray walks the top-level BVH over the surfaces and, per candidate, the surface's own BVH in its local space. The transform pieces the traversal needs (the upper 3x3 and the translation of the inverse) are cached with the surface instead of being re-derived from the matrix per ray, and a surface whose transform is exactly the identity is traced directly in world space, so the common static-geometry case pays only slab tests and triangle intersections. The lighting passes and the screen gather trace through a lean closest-hit payload (`GiShadingHit`: local position, local normal, backface flag - exactly what the surface-cache shading reads), skipping the world-space normal chain; the debug views keep the full `GiHit`.

**Direct lighting.** Valid texels accumulate the sun (with shadow rays when `lighting.sun_shadows` is on; a mesh can shadow itself) and the direct-light snapshot using the same attenuation formulas as the renderer's shading (shadow rays with `lighting.point_light_shadows`), plus their emissive term. The scattered radiance of a transparent surface carries its opacity share (the transmitted share leaves through the ray chains the transmission paths walk), so a translucent pane bounces exactly the light it keeps. Unlit surfaces store their albedo as radiance instead.

**Indirect propagation.** Budgeted texels (each card has a rotating cursor, so every texel is visited each cycle) trace `lighting.indirect_rays_per_texel` stratified cosine rays that read direct + committed indirect radiance from the surface cache; hits on geometric backfaces return zero radiance (Lumen's anti-leak rule), misses fall back to the skylight. The scattered result of a transparent texel carries the same opacity share the direct pass applies. The value blends with the previous one (`lighting.indirect_temporal_blend` is the history weight, with a ramp-up so a texel's first update takes the fresh sample), so light changes propagate over frames - one more bounce becomes correct each frame, exactly Lumen's feedback loop.

**Transmission.** Transparent and translucent surfaces (registered with an `opacity` below 1 and an `indexOfRefraction`) participate in every ray path: gather and probe rays that hit such a surface keep the surface's opacity share of its cached response and pass the rest through, tinted by the surface's albedo and bent once by Snell's law with its index ratio (exits straighten the path back out; total internal reflection mirrors). The albedo absorption applies once per medium traversal, at the entering interface, so a solid pane attenuates exactly one tint. Rays cross at most `trace.max_transmission_segments` interfaces. Shadow rays soften by the same transmittance (a transparent surface multiplies the remaining light by `(1 - opacity)` per covering hit instead of blocking it), and transparent surfaces stay out of the probe relocation and validity accounting entirely, so a probe behind a glass pane is neither pushed off the pane's plane nor marked enclosed by it.

**Caustics.** The light transmissive surfaces focus is traced as photons and deposited into the surface cache (the photon pass of the Lumen Scene): photons leave the sun and the registry's directional lights as parallel beams through each transmitter's projected area, the registry's point and spot lights as targeted cones onto the transmitter's bounding sphere (no photon is spent on empty space), and the emissive surfaces' card texels as rotating strata aimed at the transmitters. Each photon walks the same Snell / total-internal-refraction chains as every other ray, then lands on the first opaque receiver; its footprint comes from photon differentials (the center ray plus two auxiliary rays offset on the emission cell refract independently, so the triangle their landings span is the emission cell's image under the actual transport - the focus factor falls out of its area), and the flux is deposited over the covered texels with a normalized density kernel, so each photon's energy is conserved whatever the radius. Clamped footprint radii bound the estimator (a texel-sized floor stops single-texel fireflies, a scene-scale ceiling stops a degenerate differential from smearing the whole card). Photons that never cross a transparent interface deposit nothing - that light is plain direct lighting the direct pass already evaluates. The pass owns the transmitters' transmitted share: while caustics are enabled, the direct, gather, and probe rays treat a caustics transmitter as a stopper so its transmitted light is counted exactly once, by the photon deposits. Every frame re-samples the emission with fresh jitter (the per-frame deposit sum is a fresh Monte Carlo estimate of the caustic irradiance field; a frame in which no photon lands on a texel is a legitimate zero draw), the estimate blends into the card's caustic state with the configurable temporal blend (a ramp makes a texel's first deposit land whole), and the whole field decays toward the current estimate each frame the pass runs, so a caustic whose source moved away fades instead of ghosting; a receiver that moves drops its deposits (its card texels describe new world positions). The deposits ride every consumer of the surface cache exactly like the direct term: the indirect gathers bounce off caustic-lit surfaces, the world radiance cache probes carry the caustic radiance (the SH2 band limit softens it there, the same limit every small bright emitter faces), and the screen-space final gather resolves it at the captured resolution. Translucent (rough) refraction blur is not modeled - the photon chains refract geometrically, so frosted glass focuses like clear glass.

**World radiance cache.** Two camera-centered clip levels (9^3 probes each) store an octahedral radiance map plus its SH2 projection per probe. A rolling budget updates the probes each frame; each direction traces the scene, shades the hit through the surface cache, and falls back to the skylight on miss. Probes whose rays mostly strike back faces (inside geometry) are marked invalid and partial back-face shares lower the validity; back-face rays are filled with the mean of the rest. Probe rays carry the surface bias (`trace.bias_m`) along their own direction, so a probe sitting exactly on a surface plane does not self-intersect it. Probes are additionally relocated off geometry with the DDGI rules (Majercik et al. 2019; the production variant of Majercik et al. 2021): a backface ray passed through the slab it struck, so a boundary probe steps away from its closest back-face hit by exactly enough to clear that slab plus the near-surface margin - but only when the front-face rays agree that the opposite direction is open (their mean direction must lean toward it); without that agreement, or when the probe sees no front face at all, it travels through the closest back-face instead, out of the solid the short way. A probe that actually moved re-traces its whole direction map with zero hysteresis on its next update, and the planning pass serves it first, so recovery is immediate. A grazing probe is pushed out to the near-surface distance, a probe in clear space relaxes toward the near-surface equilibrium (holding the near-surface distance off any face it was pushed from, so it never drifts back across a surface), and the per-axis offset is clamped to half the level spacing (a relocated probe never crosses a neighboring lattice cell). The near-surface margin itself is the configurable `probes.relocation_margin` fraction of the spacing. The SH2 coefficients are stored irradiance-ready (see the header) and de-ringed by per-band windowing (w_l = 1 / (1 + lambda * l * (l + 1)), lambda solved per channel so the cosine irradiance stays non-negative along the 26 principal directions), which keeps more of the directional response than a uniform band shrink. Probes are exported in logical lattice order regardless of the toroidal storage. `copyProbes` exposes the grid; the header describes both levels.

**Screen-space final gather (debug view).** The module rasterizes its own GBuffer at the configured internal resolution, places jittered screen probes at `1/gather.screen_scale`, and traces `gather.rays_per_probe` directions per probe: the ray budget first rotates through every above-horizon texel of the probe's persistent 8x8 octahedral map (Lumen's screen probe directional resolution, coarser than the world probes' 32x32), and only rays beyond full strata coverage are importance-selected from the previous radiance when `gather.importance_sampling` is on; the map's history weight is the uncovered strata fraction, so it fills in across passes for small budgets and takes fresh samples each pass when the budget covers it, and it resets when its probe moves to another surface or past the placement-distance threshold. Short rays resolve near-field hits from the surface cache; misses interpolate the world cache (level 0, then level 1, then skylight). The full-resolution pass evaluates probe SH2 with the pixel normal under plane-aware weights (falling back to the world cache when no screen probe survives the plane tests, so thin geometry and silhouette borders do not drop to black), accumulates temporally through reprojection into the raw history buffer, and applies a bilateral filter into a separate display buffer - the filter is applied exactly once to whatever is shown instead of compounding across accumulation passes.

**Validation.** The `Reference` debug view path traces the same camera with next-event estimation (shadowed sun and direct lights) and cosine bounces, giving ground truth the other views can be compared against numerically. Transparent surfaces split the reference path the same deterministic way the cache's gather walks: the opacity share scatters (emission, the next-event-estimated direct response, and the indirect share its own cosine bounce collects) while the transmitted share continues refracted through the medium - the interface normal facing the ray, the albedo tint applied once at the entering interface, the exit passing untinted, and total internal reflection mirroring the path back inside - so a frosted pane's own bounce and the scene behind it are both estimated. On a two-core host, with the demo-style Cornell interior (the room as ONE mesh, lit by small emissive panels and the back wall's lit doorway, plus the freestanding frosted pane, the glass sphere, and the tinted ruby cube) and an open sunlit field with a distant hedgerow, a 60-frame converged debug-view export run reaches 0.89 of the reference's mean brightness for `FinalImage` (8-bit tone-mapped, MAE 0.10, dominated by the 64-sample reference's own Monte-Carlo noise, the emissive panels' speckle, and the probe path's soft penumbra under the occluder), 0.88 for the `ProbeIrradiance` view (MAE 0.12), and 0.93 for the renderer's probe-grid composite screenshot (MAE 0.12; the composite adds the renderer's hemispheric ambient floor and the reflection field's indirect specular over the module's own terms). The caustic deposits hold the module's overall energy: the interior's mean brightness with the caustics pass enabled sits within one percent of the pass-disabled run, with the difference concentrated in the focused light patterns themselves (arcs and crescents around the glass sphere, the ruby cube's tinted projection). Steady-state `evaluate` costs about 15-30 ms per frame on the same host with the camera orbiting and an object spinning (about 0.5 s for the companion `reflection_field` frame at the demo's half-resolution 960x540 field with its ~170k rays on the same two cores, following how much of the view its rays cover), and once the static-frame skip engages a stationary camera and scene cost nothing. Remaining known deviations: probe-based irradiance is blurrier than ground truth (world-probe spacing - a soft 1-2-cell-wide shadow of the occluder instead of the reference's crisper penumbra), small bright emitters lose some energy in the SH2 band limit exactly like Lumen's surface-cache lighting, and the caustics' resolution follows the same hierarchy as every other cached light (sharp in the surface cache and the final gather, SH2-softened in the exported probe grid). Probes whose lattice cell falls exactly on a wall or floor plane relocate off the surface (above), so a surface-hugging lattice keeps every room-side probe valid.

## Scene-extent envelope

The per-frame cost is independent of the scene's area: the probe lattice is a camera-centered clipmap (toroidally scrolled, fixed 9^3-per-level cell count), card capture, direct, indirect, and probe updates run under per-frame texel/probe budgets, and rays walk a top-level BVH whose cost is logarithmic in the registered surface count. Nothing streams and nothing rebuilds globally at world scale, so a scene of any extent - the module's contract covers planetary scales - advances at the same budgeted rate with no loading screens; the registry simply holds whatever set of surfaces the application has currently registered around the camera. World-space positions travel as float32 through the capability ABI, so scenes whose extent exceeds roughly 10^7 units from the origin degrade vertex precision before they degrade the lighting amortization - the coordinate-precision fix belongs to the engine's transform/world layer, not to this module.

## Threading and lifetime

- The module mutex serializes registry mutation, `setView`, `evaluate`, `debugExport` and `statistics`. `copyProbes` only takes a tiny snapshot mutex and returns the grid published by the last `evaluate`, so a renderer polling it never waits for a running evaluation.
- `evaluate` blocks the calling thread and runs stage chunks on scheduler workers; stage tasks write disjoint buffers and read only state frozen before the graph executes.
- Surface handles are never reused and are refused once the 32-bit handle space would wrap. Card and probe buffers rebuild when their source data changes; `stop()` drops everything and bumps the probe version.

Consumer sketch (real signatures):

```cpp
#include <engine/radiance_cache/capabilities.hpp>

auto &gi = context.acquireCapability<radiance_cache::RadianceCacheCapability>();
if (gi.abi != radiance_cache::radianceCacheCapabilityAbi)
    return; // ABI mismatch: skip rather than call through a stale struct

radiance_cache::GiSurfaceDescription box{};
box.positions = positions; box.positionStrideBytes = sizeof(float) * 3;
box.indices   = indices;   box.indexCount = indexCount;
box.opacity           = 1.0f;   // 1 = opaque; below 1 rays transmit through
box.indexOfRefraction = 1.5f;   // glass medium for the refracted continuation
box.flagBits  = radiance_cache::giSurfaceFlagDynamic;
const radiance_cache::GiSurfaceHandle handle = gi.createSurface(gi.self, &box, &error);

gi.setView(gi.self, glm::value_ptr(viewProjection), glm::value_ptr(cameraPosition));
gi.evaluate(gi.self, deltaSeconds, &error);

// Renderer-facing result: the world probe grid.
std::uint64_t            version = 0;
radiance_cache::GiProbeHeader  header{};
const std::uint32_t needed = gi.copyProbes(gi.self, nullptr, 0, &header, &version);
std::vector<radiance_cache::GiProbe> probes(needed);
gi.copyProbes(gi.self, probes.data(), static_cast<std::uint32_t>(probes.size()), &header, &version);
```

### Renderer integration note

The module is intentionally self-contained: it changes no other module. The renderer module (ABI 14) ships the approved consumer of that contract: it declares `radiance_cache` as an optional capability, polls `copyProbes` per `beginFrame` with the same version-gated pattern as the pbr environment and direct lights, and both of its backends sample the grid per pixel (trilinear-footprint SH2 interpolation with smoothstep lattice weights - the DDGI probe-blend convention, so the lattice join is C1 and the cell seams stay invisible on broad flats - `evaluateSh2Irradiance` with the pixel normal, and the shared `probeTangentPlaneFactor` anti-leak term) and use `albedo / pi * irradiance` as the indirect diffuse term, validity-renormalized over the valid probes of the trilinear footprint and blended over the hemispheric ambient through a coverage ramp (the ambient remains the fallback only while less than a quarter of the footprint's probes are valid). The CPU reference of that sampling lives in `modules/renderer/source/core/gi_probe_sampling.hpp` and its GLSL twin in `modules/renderer/shaders/mesh.frag`; `[renderer] gi_indirect_lighting` switches the hook off. The headless rasterizer amortizes the probe walk over a two-tier cache - 4x4-pixel blocks first, 2x2-pixel quads second, 8x8 and 4x4 framebuffer samples at the default 2x2 supersampling - keyed by the record (clipped triangle) that published each entry: a sample of that record reuses the entry outright (its barycentric interpolation is continuous, so the same-plane and same-normal gates pass within it by construction), a sample of another record reuses it only through the gates, and both failing runs the exact per-pixel evaluation and publishes it into the tier it missed (one walk per block on flat expanses, one per quad where the block gates fail - curvature edges, silhouettes, normal-mapped pixels - and the exact evaluation where both fail), which is what keeps the per-frame cost of the hook close to a quarter-res ambient pass. Under the same cache, the 4-wide structure-of-arrays run kernel shades probe-grid draws too (its lanes resolve their ambient samples through the cache), so a lit scene's flat expanses pay the SoA shading rate as well. The standalone `demos/lighting` application demonstrates the full loop (scene registration into both modules, per-frame `evaluate`, hook-composed output, debug views for A/B validation). It takes no command-line arguments: windowed runs use the keys (mouse look, WASD + Space/Ctrl movement, Shift sprint, 1..3 camera framings, F12 screenshot, Escape quits) and headless/capture runs are driven by DEMO_* environment variables (DEMO_FRAMES pins an exact deterministic frame count; DEMO_SCREENSHOT and DEMO_FRAME_TIMES export artifacts; the automated camera path always runs headless and DEMO_ORBIT enables it windowed). Its camera comes from the engine's `camera` module (WASD + mouse look, with Left Alt releasing the cursor) so the GI response to motion can be exercised interactively, and window resizes re-render at the new viewport. A configurable share of the scattered instances animates every frame (DEMO_DYNAMIC; renderer, radiance_cache, and reflection_field all receive the same per-frame model matrix), exercising the dynamic-surface path (moving instances carry their captured cards and re-light at the front of the queue) without manual input. The module's static-frame skip (`skip_unchanged_frames`, on by default) makes a stationary camera and scene converge and then stop consuming CPU entirely.
